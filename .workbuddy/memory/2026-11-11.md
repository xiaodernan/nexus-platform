## 第三轮（D890，同一天续做）

- 根因：该 reader 的 `blobCache` key 是 `${blame commit}|${cited path}`，blame commit 随引用所在行变化 → 上千个不同 key → 上千次 `git show` spawn。

## 本轮踩坑（复用价值高）
- **后台长任务会耗尽 Windows fork 资源**：三个 ledger falsifier 的 battery 跑 14m17s 零 verdict，期间新 Bash 命令连重定向日志文件都创建不了（表现为命令 SIGTERM、stdout 全空）。用 TaskStop 停掉即恢复。这类 harness 与 D890 的 `falsify_line_cite_drift.mjs` 同型（spawnSync 无 timeout），**必须如实记录 NOT green，不能等也不能称绿**。
- `${VAR:+-suffix}` 在 `VAR="0"` 时仍会加后缀（"0" 是非空字符串），要用 `if [ "$VAR" = 1 ]` 显式判断。
- TMPDIR 是 `C:\...\Temp` 风格；shell 里拼出的路径传给 `python - "$file" <<'PY'` 可用，但 `python -c` 内写 `/tmp/...` 会被 MSYS 改写导致找不到文件。
- `curl -o` + `python` heredoc 读 JSON 比管道 grep 稳；absence/no-drive/no-peer arm 都要先验证"服务确实起来了 + 基线干净 + 直接注册成功"，否则红得不可归因。
- CI 有大量历史 `ci.yml:NN` 引用：**接线一律改已有行的文本，不增删行**；ATLAS/CLOUD/CONTINUITY_PLAN/STATUS 无 `:NN` 引用可自由增删。
